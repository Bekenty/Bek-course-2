Ответы на контрольные вопросы9. Что такое модуль в JavaScript? Ответ: Модуль — это независимый файл JavaScript со своей собственной областью видимости. Переменные, функции или классы, объявленные внутри модуля, по умолчанию недоступны извне, пока они не будут явно экспортированы с помощью ключевого слова export, и соответственно импортированы в другой файл через import.  
 10. Чем ES-модули отличаются от обычных скриптов?Ответ: ES-модули автоматически выполняются в строгом режиме ("use strict"), имеют собственную область видимости (не загрязняют глобальную область видимости window), загружаются асинхронно и с учетом зависимостей, а также поддерживают синтаксис import / export. 
   11. Для чего нужен type="module"?Ответ: Атрибут type="module" в теге <script> указывает браузеру, что данный файл является ES-модулем. Это включает поддержку модульного синтаксиса, строгий режим и позволяет браузеру правильно обрабатывать зависимости и относительные пути.   
   12. Как работает именованный export?Ответ: Именованный экспорт (export function ...) позволяет экспортировать из файла несколько переменных или функций по их конкретным именам. При импорте в другом файле их обязательно нужно заключать в фигурные скобки: import { name1, name2 } from './module.js'.   13. Чем default export отличается от named export?Ответ: При именованном экспорте (named export) можно экспортировать несколько элементов из одного файла, и их имена при импорте должны строго совпадать (и указываться в фигурных скобках). При экспорте по умолчанию (export default) из файла экспортируется только одна главная сущность, при импорте которой можно задавать любое имя и не использовать фигурные скобки.   
   14. Почему важен путь к импортируемому файлу?Ответ: Браузер разрешает относительные пути модулей относительно текущего файла. Ошибкий в пути (например, пропущенная точка ./ или неверный уровень вложенности папок) приведет к ошибке загрузки модуля (404 Not Found), и скрипт не выполнится. 
     15. Что такое область видимости модуля?Ответ: Это изолированное пространство имен внутри конкретного файла-модуля. Объявленные там переменные и функции видны только внутри этого файла и не конфликтуют с кодом из других файлов, если они не были явно экспортированы. 
       16. Почему модульное приложение удобнее сопровождать?Ответ: Код разбивается на логические независимые блоки (файлы), что упрощает его чтение, поиск ошибок, командную разработку, повторное использование функций и масштабирование проекта. 
         17. Зачем отделять бизнес-логику от DOM?Ответ: Это позволяет изолировать чистые алгоритмы вычислений от интерфейса браузера. Благодаря этому бизнес-логику легко тестировать и переиспользовать в других проектах (или менять дизайн без переписывания расчетов).  
          18. Как диагностировать ошибку загрузки модуля?Ответ: Для этого необходимо открыть инструменты разработчика в браузере (DevTools), перейти на вкладку Console (для просмотра текста ошибок JavaScript) и вкладку Network (для проверки успешности загрузки файлов и поиска сетевых ошибок вида 404).   19.
           Почему рекомендуется запускать проект через HTTP-сервер?Ответ: Из-за политики безопасности браузеров (CORS) при открытии файлов напрямую с диска через протокол file:// блокируется загрузка ES-модулей. Локальный HTTP-сервер отдает файлы по протоколу http://, что снимает эти ограничения.  
            20. Что такое циклическая зависимость модулей?Ответ: Это ситуация, когда модуль А ссылается на модуль Б, а модуль Б в свою очередь ссылается на модуль А. Это может приводить к проблемам с порядком инициализации и появлению неопределенных (undefined) значений экспортируемых переменных.
